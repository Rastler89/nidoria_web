Seguridad

Sistema de autenticación

Implementa autenticación JWT con access_token y refresh_token almacenados en cookies mediante js-cookie. El flujo incluye registro por email, pre-registro con ventajas de fundador, y renovación automática de tokens.

🔐

Login / Registro

Formularios con validación, feedback visual y redirección post-autenticación. El login llama a /api/auth/login que retorna access_token, refresh_token y datos del usuario.

📧

Pre-registro (Fundador)

Registro temprano solo con email, pensado para la campaña de lanzamiento. Los fundadores obtienen acceso anticipado, emblema exclusivo y bonus de recursos.

🔄

Refresh automático

El API client intercepta errores 401 y ejecuta /api/auth/refresh para renovar el token sin intervención del usuario. Si falla, fuerza el logout.

🛡️

ProtectedRoute

Componente wrapper que redirige a /login si el usuario no está autenticado, protegiendo todas las rutas del dashboard.

Flujo de autenticación

// AuthProvider envuelve toda la app en layout.tsx
<AuthProvider>
  <SocketProvider>
    <ThemeProvider>
      {children}
    </ThemeProvider>
  </SocketProvider>
</AuthProvider>

// useAuth() expone:
{ user, token, login(), register(), logout(), loading }

// API Routes proxy:
POST /api/auth/login      →  { access_token, refresh_token, user }
POST /api/auth/register   →  Crea cuenta completa
POST /api/auth/refresh    →  Renueva tokens
POST /api/pre-register    →  Email-only pre-registro

Infraestructura

Sistema de Construcciones

Gestiona el crecimiento de tu colonia construyendo nuevas cámaras, almacenes y defensas. Cada edificio tiene niveles, costes en recursos y tiempos de mejora. Algunos requieren requisitos previos (otras construcciones o investigaciones).

🏗️

Edificios Construidos

Lista de estructuras operativas con su nivel actual, beneficios y opción de mejora. Las mejoras muestran coste en 🍯 🪵 🍃 🐜 y tiempo de construcción.

🔒

Proyectos Bloqueados

Estructuras avanzadas que requieren cumplir requisitos previos (ej: nivel mínimo de otra construcción). Se muestran con indicación visual de lo necesario.

⚡

Estado en Tiempo Real

Via Socket.IO, las construcciones en progreso muestran su estado actualizado, tiempo restante y finalización estimada.

// Flujo de construcción:
GET  /api/constructions    →  Lista de construcciones disponibles y activas
POST /api/constructions    →  Inicia nueva construcción o mejora
       Body: { constructionId: number }

// Socket event: anthill_update → buildings[]
{ id, name, level, status: "BUILDING"|"COMPLETED", finishingAt, update[] }

// Cada construcción tiene:
{ id, name, description, level, maxLevel, cost: { FOOD, WOOD, LEAD, ANTS, time },
  effects: { description }, requirements: [{ requiredName, requiredLevel }] }

Socket.IO — Eventos en Vivo

El cliente se conecta al servidor NestJS mediante Socket.IO con autenticación JWT. Recibe actualizaciones continuas del estado de la colonia sin necesidad de recargar.

🔌

Conexión

Se establece en SocketContext.tsx. Conecta a NEXT_PUBLIC_DB_HOST con auth: { token }. Reintento automático cada 5s.

🔄

anthill_update

Evento principal que envía el estado completo de la colonia: stats, buildings, techs, explorations.

✅

auth_error

Maneja errores de autenticación del socket. Desconecta y fuerza logout si el token expira.

// Conexión Socket.IO
import { io } from "socket.io-client";

const socket = io(process.env.NEXT_PUBLIC_DB_HOST, {
  auth: { token },
  reconnection: true,
  reconnectionDelay: 5000,
  transports: ["websocket"],
});

// Evento principal
socket.on("anthill_update", (data) => {
  // data = {
  //   stats: { eggs, larvas, ants, antsBusy },
  //   buildings: [{ id, name, level, status, finishingAt }],
  //   techs: [{ id, name, level, status }],
  //   explorations: [{ resourceType, quantity, workers }]
  // }
});
